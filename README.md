# wg-to-xray [![Launch Web App](https://img.shields.io/badge/Launch%20Web%20App-theneet0.github.io%2Fwg--to--xray-000000?style=for-the-badge&logo=googlechrome&logoColor=white)](https://theneet0.github.io/wg-to-xray/)


A client-side converter that parses standard WireGuard configuration files (`.conf`) into [Xray-core](https://github.com/XTLS/Xray-core) outbound JSON objects and standard `wireguard://` client connection URIs.

Runs entirely in the browser with zero server dependencies, external requests, or network telemetry.

---

## Overview

WireGuard configurations generated by commercial VPN providers, Cloudflare WARP, or self-hosted servers use INI-style syntax (`[Interface]` and `[Peer]`). Routing these configurations through Xray-core requires translating directives into Xray's `wireguard` outbound protocol schema.

`wg-to-xray` automates this conversion process while preserving all parameters, addressing format edge cases, and generating both:
1. **Xray Outbound JSON**: Ready to insert into your Xray client or server configuration.
2. **WireGuard Connection URI**: Formatted as `wireguard://<private_key>@<endpoint>?<params>#<tag>` for importing into mobile or desktop clients that support standard WireGuard share links.

## Transformation Example

### Input (`de-frankfurt.conf`)
```ini
[Interface]
PrivateKey = aaaaaa...=
Address = 172.16.0.2/32, fd00::2/128
DNS = 1.1.1.1, 1.0.0.1
Reserved = [142, 201, 88]

[Peer]
PublicKey = bbbbbb...=
Endpoint = 198.51.100.1:51820
AllowedIPs = 0.0.0.0/0, ::/0
PersistentKeepalive = 25
```

### Generated Xray Outbound JSON
```json
{
  "tag": "de-frankfurt",
  "protocol": "wireguard",
  "settings": {
    "secretKey": "aaaaaa...=",
    "address": [
      "172.16.0.2/32",
      "fd00::2/128"
    ],
    "remoteDNS": [
      "1.1.1.1",
      "1.0.0.1"
    ],
    "reserved": [
      142,
      201,
      88
    ],
    "noKernelTun": true,
    "domainStrategy": "ForceIP",
    "peers": [
      {
        "publicKey": "bbbbbb...=",
        "endpoint": "198.51.100.1:51820",
        "allowedIPs": [
          "0.0.0.0/0",
          "::/0"
        ],
        "keepAlive": 25
      }
    ]
  }
}
```

### Generated WireGuard URI
```text
wireguard://aaaaaa...%3D@198.51.100.1:51820?address=172.16.0.2%2F32%2Cfd00%3A%3A2%2F128&dns=1.1.1.1%2C1.0.0.1&publickey=bbbbbb...%3D&allowedips=0.0.0.0%2F0%2C%3A%3A%2F0&reserved=142%2C201%2C88&keepalive=25#de-frankfurt
```

## Field & Directive Mapping Reference

| WireGuard Directive | Recognized Aliases | Xray-core Target | URI Parameter | Conversion Details |
|---|---|---|---|---|
| `PrivateKey` | `SecretKey`, `PrivKey` | `settings.secretKey` | `wireguard://<key>@` | Base64 URL-encoded in URI authority |
| `Address` | `Addresses`, `IP`, `LocalAddress` | `settings.address` | `?address=...` | Normalized into CIDR array |
| `DNS` | `RemoteDNS`, `Nameserver` | `settings.remoteDNS` | `&dns=...` | Transferred to remote DNS resolution list |
| `MTU` | `mtu` | `settings.mtu` | `&mtu=...` | Preserved **only** if explicitly defined in input |
| `Reserved` | `X-Reserved`, `Reserved` | `settings.reserved` | `&reserved=...` | Decodes 3-byte decimal lists, hex, or 4-char Base64/Base64URL |
| `PublicKey` | `Pubkey`, `PeerPublicKey` | `peers[].publicKey` | `&publickey=...` | Peer identity public key |
| `Endpoint` | `Server`, `Remote`, `Host` | `peers[].endpoint` | `@<host>:<port>` | Hostname or IP with mandatory port |
| `AllowedIPs` | `Allowed`, `Routing` | `peers[].allowedIPs` | `&allowedips=...` | Comma- or space-separated routing prefixes |
| `PresharedKey` | `PSK`, `SharedKey` | `peers[].preSharedKey` | `&presharedkey=...` | Optional post-quantum symmetric key |
| `PersistentKeepalive` | `Keepalive` | `peers[].keepAlive` | `&keepalive=...` | Integer seconds; omitted when not specified |

## Parser Rules & Behavior

1. **Non-destructive Defaulting**:
   Attributes such as `MTU` and `PersistentKeepalive` are never injected with arbitrary fallback values (e.g. `1420` or `25`). If the source configuration does not declare them, they are excluded from the output.
2. **Automatic Tag Derivation**:
   When loading a `.conf` file via file selection or drag-and-drop, the tag defaults to the profile's basename without the file extension (e.g., `WARP-US.conf` &rarr; `WARP-US`).
3. **Multi-Peer Handling**:
   Configurations with multiple `[Peer]` sections generate:
   - A single Xray outbound with all peers under `settings.peers`.
   - Distinct, numbered connection URIs (`tag-1`, `tag-2`, etc.) for client import.
4. **Cloudflare WARP Reserved Byte Decoding**:
   Handles decimal arrays (`[0, 0, 0]`), quoted values (`"1, 2, 3"`), hex notation, and 4-character Base64 / Base64URL encodings (e.g., `AAAA`, `a-b_`).
5. **Key Normalization**:
   Directives containing spaces, underscores, or hyphens (e.g. `allowed_ips`, `pre-shared-key`) are parsed identically to canonical casing.

## Deployment & Usage

### Web Interface
Open the application directly in your web browser:
&rarr; **[https://theneet0.github.io/wg-to-xray/](https://theneet0.github.io/wg-to-xray/)**

### Running Locally
Because the project contains no build steps, compilers, or heavy node runtimes, it can be hosted using any static file server:

```bash
git clone https://github.com/theneet0/wg-to-xray.git
cd wg-to-xray

# Using Python 3
python -m http.server 8080

# Or using Node.js
npx serve .
```

Open `http://localhost:8080` in any modern web browser.

### Programmatic Usage (Node.js)
The core parser can also be imported in Node scripts:

```javascript
const { parseWireguardConfig, buildXrayConfig, buildWireguardUri } = require('./converter.js');

const rawConf = `
[Interface]
PrivateKey = aaaaaa...=
Address = 10.0.0.2/32

[Peer]
PublicKey = bbbbbb...=
Endpoint = 198.51.100.1:51820
AllowedIPs = 0.0.0.0/0
`;

const parsed = parseWireguardConfig(rawConf);
const { config, warnings } = buildXrayConfig(parsed, { tag: "prod-vpn" });
const uris = buildWireguardUri(parsed, { tag: "prod-vpn" });

console.log(JSON.stringify(config, null, 2));
console.log(uris[0]);
```
